# Database Seeding

This document describes the database seeding system for populating the database with realistic test data.

## Overview

The seed command (`cmd/seed`) uses the [faker library](https://github.com/jaswdr/faker) to generate randomized but realistic test data. It's designed for development and testing purposes.

## Usage

### Basic Seeding

```bash
# Seed with random data
make seed

# Or directly
go run ./cmd/seed
```

### Reproducible Seeding

For consistent data across team members or CI:

```bash
# Use a specific seed value
make seed-reproducible  # Uses seed=42

# Or with custom seed
go run ./cmd/seed -seed 123
```

## What Gets Seeded

The seeder creates a realistic dataset in this order:

### 1. Churches (8 churches)
- Mix of sizes: S, L, XL
- Across Nordic countries: Norway, Sweden, Denmark, Finland
- Realistic church names

### 2. Users (75 users)
- Distributed across all churches
- Realistic names based on gender using faker
- Ages 13-80
- Random genders (male, female, other)
- Profile avatars from pravatar.cc
- Unique members IDs

### 3. Projects (3 projects)
- Past, current, and future projects
- One archived project
- Realistic branding (colors, logo, font)
- Date ranges that make sense

### 4. Events (3-5 per project)
- Spread across project duration
- Realistic locations using faker
- 3-day duration each

### 5. Streaks (1-2 per project)
- 7-28 day durations
- Relevant date ranges matching project dates

### 6. Super Teams (2-3 per project)
- Company-style names using faker
- Profile avatars

### 7. Teams (8-12 per project)
- Job title-based names using faker
- 50% chance to belong to a SuperTeam
- Unique join codes
- 5-15 members per team
- Users automatically added to projects when joining teams

### 8. Challenges (15-25 per project)
- Random points (10-100)
- 30% linked to events
- 40% have end times
- 80% are published
- Realistic names and descriptions

### 9. Achievements (per project)
- **Simple** (5-8): Basic achievements with points
- **Reading** (2-4): Each with 3-6 articles
  - Article titles, authors, URLs, estimated reading time
- **Listening** (2-4): Each with 4-8 tracks
  - Track titles, artists, URLs, duration
- **Streak** (1-2): One per streak with required days
- 40% linked to events
- 50% of simple achievements linked to challenges

### 10. Progress Data
- **User Achievements**: 20-30 random achievements awarded
- **Challenge Completions**: 30-50 random completions
- All with realistic timestamps (past 30 days)

## Data Characteristics

### Randomization

- Names: Generated by faker based on gender
- Dates: Calculated relative to current date
- Points: Multiplies of 5 or 10
- URLs: Generated by faker
- Colors: Random hex colors
- Descriptions: Lorem ipsum sentences

### Relationships

- Users belong to one church
- Users can be in multiple teams (one project per team)
- Teams can belong to SuperTeams
- Achievements can be linked to events and/or challenges
- Progress data references existing users and achievements

## Idempotency

The seed command is **idempotent** and uses a "clear and reseed" strategy:

1. **Truncates all tables** in reverse dependency order
2. **Seeds fresh data** with new random values
3. **Safe to run multiple times** without manual cleanup

**Warning**: This DELETES ALL DATA. Never run in production!

## Implementation Details

### File Structure

```
cmd/seed/
├── main.go              # Entry point, orchestration, database clearing
└── seeders/
    ├── seeder.go        # Base seeder struct and shared data
    ├── churches.go      # Church seeding
    ├── users.go         # User seeding with faker
    ├── projects.go      # Projects, events, and streaks
    ├── teams.go         # SuperTeams, teams, and member assignment
    ├── challenges.go    # Challenge seeding
    ├── achievements.go  # All 4 achievement types
    └── progress.go      # User progress and completions
```

### Seeder Pattern

Each seeder:
1. Receives a `Seeder` struct with DB connection and faker instance
2. Updates `SeededData` to track IDs for cross-referencing
3. Increments `Stats` counters
4. Returns error on any database failure

### Data Tracking

The `SeededData` struct tracks all created IDs:
- Enables cross-referencing (e.g., assigning users to teams)
- Allows random selection (e.g., linking achievements to events)
- Maintains referential integrity

## Extending the Seeder

To add new data types:

1. Create a new seeder file in `cmd/seed/seeders/`
2. Add method to `Seeder` struct
3. Update `SeededData` if needed for cross-referencing
4. Add stats counter to `Stats` struct
5. Call from `main.go` in appropriate order
6. Update `clearDatabase()` if new tables added

Example:

```go
// cmd/seed/seeders/badges.go
func (s *Seeder) SeedBadges(stats *Stats) error {
    // Your seeding logic
    stats.Badges++
    return nil
}

// cmd/seed/main.go
slog.Info("Seeding badges")
if err := seeder.SeedBadges(stats); err != nil {
    slog.Error("Failed to seed badges", "error", err)
    os.Exit(1)
}
```

## Troubleshooting

### "Failed to clear database"

**Issue**: Cannot truncate tables

**Solutions**:
- Check database permissions
- Verify all tables exist (run migrations first)
- Check for foreign key constraint issues

### "Failed to seed X"

**Issue**: Seeding failed for specific entity type

**Solutions**:
- Check logs for specific SQL error
- Verify schema matches seeder expectations
- Check ULID generation for entity type
- Ensure previous seeders completed successfully

### Slow Seeding

**Issue**: Seed takes too long

**Solutions**:
- Reduce counts in seeders (adjust rand ranges)
- Use batch inserts (currently one-by-one)
- Check database connection latency
- Consider using COPY for bulk data
